# AGENTS.md

# Инструкции для Codex

## 1. Назначение проекта

Проект предназначен для разработки кроссплатформенного Python-приложения для автоматизации подготовки проектной документации ВЛ 0,4 кВ.

Приложение должно помогать инженеру формировать пояснительную записку и итоговый PDF-комплект на основе уже готовых исходных файлов.

Пользователь вручную готовит план в AutoCAD. Программа не проектирует линию и не расставляет опоры. Программа только читает готовый план, извлекает данные, рассчитывает значения и подставляет их в эталонную DWG-записку.

---

## 2. Основной пользовательский сценарий

Пользователь открывает приложение и выбирает:

1. ТУ в формате DOCX или PDF.
2. Готовый план ВЛ в формате DWG/DXF.
3. Эталонную пояснительную записку `template_note.dwg`.
4. Excel-файл расчёта арматуры `armature_calc.xlsx`.
5. Папку для результата.
6. Вручную вводит номер проекта в поле интерфейса.

Пример вводимого номера проекта:

```text
ПСД/48/2026/052
```

Этот номер проекта должен использоваться для placeholder:

```text
{{PROJNUMB}}
```

Важно: `{{PROJNUMB}}` — это значение, которое пользователь вводит на фронтенде. Это не имя папки и не обязательно значение из ТУ.

После нажатия кнопки **Старт** программа должна:

1. Прочитать ТУ.
2. Извлечь из ТУ текстовые и технические параметры.
3. Принять номер проекта из поля интерфейса и записать его в `project_data.json`.
4. Прочитать готовый план.
5. Посчитать длину основной полилинии.
6. Посчитать блоки опор и заземлений.
7. Выполнить расчёты материалов и производных значений.
8. Сформировать `project_data.json`.
9. Сформировать `replacement_map.json`.
10. Создать копию `template_note.dwg` в папке результата.
11. На Windows позже заменить placeholders в копии DWG-записки через AutoCAD COM API.
12. На Windows позже экспортировать план и записку в PDF.
13. Объединить PDF плана и PDF записки в единый итоговый PDF.

## 3. Платформенная логика

Проект должен изначально разрабатываться и тестироваться на macOS, но архитектура должна позволять дальнейший запуск на Windows.

### macOS, первый этап

На macOS нужно реализовать:

- графический интерфейс;
- поле ввода номера проекта для `{{PROJNUMB}}`;
- чтение ТУ DOCX/PDF;
- чтение DXF-плана через `ezdxf`;
- подсчёт длины полилинии;
- подсчёт блоков опор и заземлений;
- расчёты по формулам;
- формирование JSON-файлов;
- копирование DWG-шаблона в `output/`;
- mock-режим для DWG-редактирования.

На macOS не нужно напрямую редактировать DWG через AutoCAD COM API.

### Windows, следующий этап

На Windows нужно добавить отдельный CAD-адаптер:

- работа с AutoCAD через `pywin32` / COM API;
- открытие DWG-плана;
- открытие копии DWG-шаблона записки;
- поиск placeholders вида `{{FIELD_NAME}}`;
- замена placeholders на значения из `replacement_map.json`;
- сохранение готового DWG;
- экспорт плана в PDF;
- экспорт записки в PDF;
- объединение PDF.

## 4. Главное архитектурное правило

Core-логика не должна зависеть от AutoCAD, Windows, COM API или `pywin32`.

Нужно разделить проект на:

```text
core/      — общая логика, работает на macOS и Windows
cad/       — CAD-адаптеры: mock, DXF, AutoCAD Windows
ui/        — графический интерфейс
examples/  — примеры и правила
output/    — результаты работы программы
```

AutoCAD должен быть отдельным исполнителем, а не ядром программы.

## 5. Что программа НЕ должна делать

Программа не должна:

- проектировать план;
- рисовать трассу ВЛ;
- расставлять опоры;
- исправлять геометрию плана;
- перемещать объекты на плане;
- менять растровую подложку;
- менять исходный `template_note.dwg`;
- менять структуру пояснительной записки;
- менять рамки, таблицы, листы, шрифты и оформление записки;
- использовать введённый пользователем `{{PROJNUMB}}` как обязательное имя папки;
- работать с оригиналами файлов без создания копии.

---

## 6. Что программа должна делать с планом

План создаётся инженером вручную в AutoCAD.

Программа должна только читать готовый план и извлекать:

- длину основной полилинии ВЛ;
- количество опор П23;
- количество опор А23;
- количество опор УА23*;
- количество опор К21;
- количество заземлений.

На macOS программа читает DXF через `ezdxf`.

На Windows позже можно добавить чтение DWG через AutoCAD COM API.

Результат чтения плана сохраняется в:

```text
plan_data.json
```

Пример структуры:

```json
{
  "line_length_m": 120.0,
  "line_length_km": 0.12,
  "supports": {
    "P23": 3,
    "A23": 1,
    "YA23": 1,
    "K21": 1
  },
  "grounding_count": 2
}
```

## 7. Что программа должна делать с пояснительной запиской

Эталонная пояснительная записка хранится в файле:

```text
examples/templates/template_note.dwg
```

Внутри неё должны быть заранее вручную расставлены placeholders вида:

```text
{{APPLICANT}}
{{ADRESS}}
{{KADNUMBER}}
{{PROJNUMB}}
{{DATE}}
{{SECH_KABEL}}
{{FAZE}}
{{OTKUDASTROIT}}
{{TP_NAME}}
{{SQUARE}}
{{LINE_LENGTH_M}}
{{LINE_LENGTH_KM}}
{{P23}}
{{A23}}
{{YA23}}
{{K21}}
{{GROUND}}
```

Главный номер проекта, который вводится пользователем на фронтенде, должен заменять именно:

```text
{{PROJNUMB}}
```

Если в шаблоне остался старый placeholder `{{PROJECTNUMBER}}`, его нужно либо заменить в DWG на `{{PROJNUMB}}`, либо явно оставить как отдельное поле из ТУ. Нельзя смешивать эти placeholders без правила.

Программа должна:

1. Никогда не изменять исходный `template_note.dwg`.
2. Создавать копию шаблона в `output/`.
3. На macOS только формировать `replacement_map.json` и копировать шаблон.
4. На Windows через AutoCAD COM API заменять placeholders только в копии DWG.

## 10. Файлы правил

### `fields_map.md`

Описывает placeholders для пояснительной записки:

- что означает поле;
- откуда берётся значение;
- пример значения;
- формула, если поле рассчитывается.

`{{PROJNUMB}}` должен быть описан как номер проекта, вводимый пользователем на фронтенде.

### `autocad_blocks.md`

Описывает соответствие блоков AutoCAD инженерным типам:

```text
имя блока AutoCAD -> тип опоры / заземление
```

Пример:

```text
Пл_ОпораНВ_А23 -> А23
```

### `plan_reading_rules.md`

Описывает, как читать готовый план:

- не строить план;
- читать полилинию;
- считать блоки опор;
- считать заземления;
- сохранять результат в `plan_data.json`.

### `excel_map.md`

Описывает, как использовать Excel-лист `Линейная арматура`.

Логика:

- сверху расположены типы опор;
- слева расположена арматура;
- на пересечении находится коэффициент;
- количество материала считается как количество опор, умноженное на коэффициент.

Пример:

```text
если сверху П23, слева F207, на пересечении стоит 2,
то F207 от П23 = количество П23 * 2
```

## 11. Ключевые placeholders и формулы

### Данные с фронтенда

```text
{{PROJNUMB}} = номер проекта, который пользователь вводит в интерфейсе
```

Пример:

```text
ПСД/48/2026/052
```

В `replacement_map.json` должно быть:

```json
{
  "{{PROJNUMB}}": "ПСД/48/2026/052"
}
```

### Данные из плана

```text
{{LINE_LENGTH_M}} = длина основной полилинии, м
{{LINE_LENGTH_KM}} = {{LINE_LENGTH_M}} / 1000
{{P23}} = количество опор П23
{{A23}} = количество опор А23
{{YA23}} = количество опор УА23*
{{K21}} = количество опор К21
{{GROUND}} = количество заземлений
```

### Площадь отвода земли

```text
{{SQUARE}} = {{LINE_LENGTH_M}} * 4
```

### Фазность

```text
если ТУ содержит однофазный -> {{FAZE}} = однофазный
если ТУ содержит трехфазный или трёхфазный -> {{FAZE}} = трехфазный
```

### Счётчик

```text
если {{FAZE}} = трехфазный -> {{FOBOS_FAZE}} = ФОБОС 3
если {{FAZE}} = однофазный -> {{FOBOS_FAZE}} = ФОБОС 1
```

### Щит

```text
если {{FAZE}} = трехфазный -> {{SHIT}} = КМПн-8
если {{FAZE}} = однофазный -> {{SHIT}} = КМПн-4
```

### Количество модулей

```text
если {{FAZE}} = трехфазный -> {{QUANTITY}} = 8
если {{FAZE}} = однофазный -> {{QUANTITY}} = 4
```

### СИП-4

```text
если {{FAZE}} = трехфазный -> {{SECH_SIP4}} = 4x16
если {{FAZE}} = однофазный -> {{SECH_SIP4}} = 2x16
```

### Сечение кабеля

```text
если в ТУ написано "сечением кабеля от 50 до 70" -> {{SECH_KABEL}} = 3x70+1x70
если в ТУ написано "сечением кабеля до 50" -> {{SECH_KABEL}} = 3x50+1x50
```

### Длина кабеля с запасом

```text
{{SECH_KM}} = {{LINE_LENGTH_KM}} * 1.045
```

### Масса кабеля

```text
если {{SECH_KABEL}} = 3x70+1x70 -> {{SECH_KG}} = {{SECH_KM}} * 1112
если {{SECH_KABEL}} = 3x50+1x50 -> {{SECH_KG}} = {{SECH_KM}} * 775
```

### Общее количество опор

```text
{{S}} = {{P23}} + {{A23}} + {{YA23}} + {{K21}}
```

### Бетон по типам опор

```text
{{P23_1}} = {{P23}} * 0.36
{{YA231}} = {{YA23}} * 0.9
{{K21_1}} = {{K21}} * 0.45
{{S1}} = {{P23_1}} + {{YA231}} + {{K21_1}}
```

### Стойки

```text
{{5}} = {{K21}} * 1 + {{YA23}} * 2
{{51}} = {{5}} * 0.45
{{3}} = {{P23}} * 1 + {{A23}} * 2
{{31}} = {{3}} * 0.36
```

### Заземляющий проводник

```text
{{ZP6}} = {{P23}} * 0.3 + {{YA23}} * 1 + {{K21}} * 0.65 + {{A23}} * 0.65
```

### Арматура

```text
{{X89}} = {{YA23}}
{{F207}} = {{P23}} * 2 + {{YA23}} * 4 + {{K21}} * 2 + {{A23}} * 2 + 6
{{NC20}} = {{F207}}
{{ES15}} = {{P23}}
{{CS10}} = {{K21}} * 2 + {{A23}} * 2 + {{YA23}} * 2
{{PA15}} = {{CS10}}
{{P95}} = 4
{{P72}} = {{S}}
{{CD35}} = {{P23}} * 1 + {{A23}} * 2 + {{K21}} * 2 + {{YA23}} * 2
{{E778}} = {{S}} * 2
{{GR}} = {{GROUND}} * 3
```

### Зажим для ответвления жилы СИП

```text
если {{FAZE}} = трехфазный -> {{P645}} = 4
если {{FAZE}} = однофазный -> {{P645}} = 2
```

## 12. Важное замечание по названиям placeholders

Нужно использовать одинаковые названия placeholders во всех местах.

Для номера проекта с титульного листа использовать:

```text
{{PROJNUMB}}
```

Не использовать `{{PROJECTNUMBER}}` для этого же значения, если в DWG-шаблоне уже используется `{{PROJNUMB}}`.

Сейчас встречаются разные варианты:

```text
{{ADRESS}} и {{ADDRESS}}
{{TP_NAME}} и {{TO_NAME}}
{{OTKUDASTROIT}} и {{OTUDASTROIT}}
{{PROJNUMB}} и {{PROJECTNUMBER}}
```

Перед реализацией нужно выбрать один вариант для каждого значения и использовать его везде.

Рекомендуемые варианты:

```text
{{ADRESS}} — если уже так стоит в DWG-шаблоне
{{TP_NAME}}
{{OTKUDASTROIT}}
{{PROJNUMB}}
```

Главное правило: названия placeholders должны совпадать символ в символ.

## 17. Главный итог

Нужно создать систему, которая работает по принципу:

```text
номер проекта с фронтенда + ТУ + готовый план + Excel + DWG-шаблон
        ↓
извлечение данных
        ↓
расчёты
        ↓
replacement_map.json
        ↓
копия DWG-записки
        ↓
на Windows: замена placeholders и экспорт PDF
```

Главная цель — убрать ручную замену данных в пояснительной записке и ручной расчёт повторяющихся материалов.
