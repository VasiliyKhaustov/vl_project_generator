# plan_reading_rules.md

# Правила чтения готового плана ВЛ 0,4 кВ

## 1. Главный принцип

Программа **не должна проектировать план** и **не должна расставлять опоры**.

План создаётся инженером вручную в AutoCAD. Программа должна только открыть готовый план и извлечь из него данные для пояснительной записки и расчёта материалов.

Программа не должна:

- рисовать трассу;
- расставлять опоры;
- менять положение опор;
- менять растровую подложку;
- менять геометрию плана;
- исправлять ошибки в плане;
- заменять или перемещать блоки.

Программа должна:

- прочитать готовый план;
- найти основную полилинию ВЛ;
- определить длину линии;
- посчитать установленные блоки опор;
- посчитать установленные блоки заземления;
- сформировать данные для пояснительной записки;
- сформировать значения для placeholders в `template_note.dwg`.

---

## 2. Номер проекта с фронтенда

Номер проекта вводится пользователем в интерфейсе приложения.

Пример:

```text
ПСД/48/2026/052
```

Этот номер должен записываться в placeholder:

```text
{{PROJNUMB}}
```

Важно:

- `{{PROJNUMB}}` не берётся из плана.
- `{{PROJNUMB}}` не берётся из Excel.
- `{{PROJNUMB}}` не должен использоваться как обязательное имя папки.
- `{{PROJNUMB}}` должен попадать в `project_data.json` и `replacement_map.json`.

Пример `replacement_map.json`:

```json
{
  "{{PROJNUMB}}": "ПСД/48/2026/052"
}
```

Если в старых правилах или шаблонах используется `{{PROJECTNUMBER}}`, а фактически нужен номер проекта с титульного листа, то его нужно заменить на `{{PROJNUMB}}`.

## 3. Количество примеров

В папке `examples/projects/` будет не три проекта, а **два реальных проекта**.

Структура должна быть такой:

```text
examples/projects/
  project_01/
    tu.docx
    tu.pdf
    plan.dwg
    plan.dxf
    note.dwg
    final_result.pdf

  project_02/
    tu.docx
    tu.pdf
    plan.dwg
    plan.dxf
    note.dwg
    final_result.pdf
```

На macOS первый этап работает через DXF. На Windows позже добавляется работа с DWG через AutoCAD COM API.

## 4. Источники данных

Данные берутся из четырёх источников:

1. **Фронтенд** — номер проекта `{{PROJNUMB}}`.
2. **ТУ DOCX/PDF** — заявитель, адрес, кадастровый номер, дата, фазность, ТП, сечение кабеля и прочие текстовые параметры.
3. **Готовый план DWG/DXF** — длина линии, количество опор, количество заземлений.
4. **Расчётные правила** — производные значения, которые рассчитываются по формулам.

## 5. Чтение готового плана

### 5.1. Основная полилиния

В плане должна быть одна основная полилиния трассы ВЛ.

Программа должна:

- найти основную полилинию ВЛ;
- определить её длину в метрах;
- записать длину в `{{LINE_LENGTH_M}}`;
- перевести длину в километры и записать в `{{LINE_LENGTH_KM}}`.

Формулы:

```text
{{LINE_LENGTH_M}} = длина основной полилинии, м
{{LINE_LENGTH_KM}} = {{LINE_LENGTH_M}} / 1000
```

Если в плане несколько полилиний, программа должна выбрать основную полилинию ВЛ по правилу, которое будет отдельно уточнено: слой, имя, длина или ручной выбор пользователем.

---

### 5.2. Опоры

Опоры уже стоят на плане. Программа должна только посчитать блоки.

Типы опор:

```text
П23   -> {{P23}}
А23   -> {{A23}}
УА23* -> {{YA23}}
К21   -> {{K21}}
```

Программа должна использовать справочник `autocad_blocks.md`, где указано соответствие:

```text
имя блока AutoCAD -> инженерный тип опоры
```

Например:

```text
Пл_ОпораНВ_А23 -> А23
```

Результат:

```text
{{P23}} = количество найденных блоков П23
{{A23}} = количество найденных блоков А23
{{YA23}} = количество найденных блоков УА23*
{{K21}} = количество найденных блоков К21
```

---

### 5.3. Заземления

Заземления уже стоят на плане как отдельные блоки.

Программа должна:

- найти блоки заземления;
- посчитать их количество;
- записать результат в `{{GROUND}}`.

Формула:

```text
{{GROUND}} = количество найденных блоков заземления
```

Общее количество заземления для спецификации:

```text
{{GR}} = {{GROUND}} * 3
```

## 6. Поля из ТУ

Эти значения программа должна извлекать из ТУ DOCX/PDF.

```text
{{APPLICANT}} = заявитель
{{ADRESS}} = адрес объекта
{{KADNUMBER}} = кадастровый номер земельного участка
{{DATE}} = дата проекта / дата договора / дата из ТУ
{{OTKUDASTROIT}} = откуда строить линию
{{TP_NAME}} = номер ТП / наименование ТП
{{FAZE}} = однофазный или трехфазный
{{SECH_KABEL}} = сечение кабеля
```

Важно: `{{PROJNUMB}}` не относится к ТУ. Его вводит пользователь на фронтенде.

---

## 7. Производные поля по фазности

```text
если {{FAZE}} = трехфазный -> {{FOBOS_FAZE}} = ФОБОС 3
если {{FAZE}} = однофазный -> {{FOBOS_FAZE}} = ФОБОС 1

если {{FAZE}} = трехфазный -> {{SHIT}} = КМПн-8
если {{FAZE}} = однофазный -> {{SHIT}} = КМПн-4

если {{FAZE}} = трехфазный -> {{QUANTITY}} = 8
если {{FAZE}} = однофазный -> {{QUANTITY}} = 4

если {{FAZE}} = трехфазный -> {{SECH_SIP4}} = 4x16
если {{FAZE}} = однофазный -> {{SECH_SIP4}} = 2x16

если {{FAZE}} = трехфазный -> {{P645}} = 4
если {{FAZE}} = однофазный -> {{P645}} = 2
```

---

## 8. Производные поля по длине линии

```text
{{SQUARE}} = {{LINE_LENGTH_M}} * 4
{{LINE_LENGTH_KM}} = {{LINE_LENGTH_M}} / 1000
{{SECH_KM}} = {{LINE_LENGTH_KM}} * 1.045
```

Масса кабеля:

```text
если {{SECH_KABEL}} = 3x70+1x70 -> {{SECH_KG}} = {{SECH_KM}} * 1112
если {{SECH_KABEL}} = 3x50+1x50 -> {{SECH_KG}} = {{SECH_KM}} * 775
```

## 9. Производные поля по количеству опор

```text
{{S}} = {{P23}} + {{A23}} + {{YA23}} + {{K21}}

{{P23_1}} = {{P23}} * 0.36
{{YA231}} = {{YA23}} * 0.9
{{K21_1}} = {{K21}} * 0.45
{{S1}} = {{P23_1}} + {{YA231}} + {{K21_1}}

{{5}} = {{K21}} * 1 + {{YA23}} * 2
{{51}} = {{5}} * 0.45

{{3}} = {{P23}} * 1 + {{A23}} * 2
{{31}} = {{3}} * 0.36
```

## 11. Результаты работы модуля чтения плана

После анализа плана программа должна сформировать файл:

```text
plan_data.json
```

Пример структуры:

```json
{
  "line_length_m": 120.0,
  "line_length_km": 0.12,
  "supports": {
    "P23": 3,
    "A23": 1,
    "YA23": 1,
    "K21": 1
  },
  "grounding_count": 2
}
```

После объединения данных из фронтенда, ТУ, плана и расчётных правил программа должна сформировать:

```text
project_data.json
replacement_map.json
```

`replacement_map.json` должен содержать готовые значения для замены placeholders в `template_note.dwg`, включая:

```json
{
  "{{PROJNUMB}}": "ПСД/48/2026/052"
}
```

---

## 12. Важные правила для Codex

1. Не менять план.
2. Не строить план.
3. Не расставлять опоры.
4. Не менять исходный `template_note.dwg`.
5. Всегда создавать копию шаблона в `output/`.
6. На macOS не редактировать DWG напрямую.
7. На macOS использовать DXF и `ezdxf` для чтения плана.
8. На Windows позже добавить отдельный AutoCAD-адаптер через COM API.
9. Core-логика должна быть кроссплатформенной.
10. Все формулы должны быть вынесены в отдельный модуль расчётов.
11. `{{PROJNUMB}}` должен браться из поля ввода интерфейса, а не из ТУ.

## 13. Поля, которые нужно унифицировать перед разработкой

В текущих описаниях встречаются разные варианты написания некоторых placeholders. Перед разработкой нужно выбрать один вариант и использовать его везде: в DWG-шаблоне, `fields_map.md`, `plan_reading_rules.md` и коде.

Использовать для номера проекта с титульного листа:

```text
{{PROJNUMB}}
```

Если где-то используется `{{PROJECTNUMBER}}` для того же самого значения, заменить на `{{PROJNUMB}}`.

Также проверить:

```text
{{ADRESS}} / {{ADDRESS}}
{{TP_NAME}} / {{TO_NAME}}
{{OTKUDASTROIT}} / {{OTUDASTROIT}}
```

Главное — чтобы названия placeholders совпадали абсолютно точно.
