# TU Automation

Локальное web-приложение для подготовки данных проектной документации по ТУ.

## MVP

- FastAPI backend.
- Single-page frontend.
- Ввод номера проекта `project_number`.
- Запись `{{PROJNUMB}}` в `replacement_map.json`.
- Чтение DOCX/PDF ТУ.
- Чтение DXF-плана через `ezdxf`.
- Расчёт производных значений.
- Копирование `examples/templates/template_note.dwg` в `output/result/dwg/note_result.dwg`.

На macOS DWG не редактируется. AutoCAD COM API остаётся для Windows-этапа.

## Автоматический расчёт километража до РЭС

При обработке ТУ программа:

1. Извлекает кадастровый номер участка заявителя.
2. По тексту ТУ определяет район/город и выбирает адрес РЭС.
3. Получает координаты кадастрового участка через provider-адаптеры кадастровых API.
4. Геокодирует адрес РЭС.
5. Строит автомобильный маршрут и округляет расстояние вверх до целого километра.
6. Подставляет значение вместо хардкода `23 км` в записке через `{{ROUTE_DISTANCE_KM}}`.

Поддерживаемые правила выбора РЭС:

| Район/город в ТУ | Адрес РЭС |
| --- | --- |
| город Липецк, г. Липецк, Липецкий район | Липецкая область, Липецк, улица Механизаторов, 16 |
| Данков, Данковский район | Липецкая область, Данков, Коммунальная улица, 23 |
| Чаплыгин, Чаплыгинский район, Доброе, Добровский район | Липецкая область, село Доброе, Советская улица, 58А |
| Грязи, Грязинский район, Грузинский район (опечатка) | Липецкая область, Грязи, Песковатская улица, 7 |
| Добринка, Добринский район | Липецкая область, Добринский район, посёлок Добринка, Профсоюзная улица, 8 |

Важно: фраза `Липецкая область` сама по себе не выбирает Липецкий РЭС.

### Переменные окружения

Маршрутизация и геокодирование работают через fallback-цепочку провайдеров. Ключи задаются в `.env` или окружении:

```bash
YANDEX_MAPS_API_KEY=...
TWOGIS_API_KEY=...
GRAPHHOPPER_API_KEY=...
OPENROUTESERVICE_API_KEY=...
OSRM_BASE_URL=https://router.project-osrm.org
```

Приоритет маршрутизации:

1. Yandex Routing (если есть `YANDEX_MAPS_API_KEY`)
2. 2GIS (если есть `TWOGIS_API_KEY`)
3. GraphHopper (если есть `GRAPHHOPPER_API_KEY`)
4. OpenRouteService (если есть `OPENROUTESERVICE_API_KEY`)
5. OSRM (публичный или свой `OSRM_BASE_URL`)

Если API-ключей нет, приложение не падает: в предупреждениях появится понятная ошибка, а `23 км` в записке останется без замены.

### Ошибки

- **Кадастровый номер не найден** — проверьте, что в ТУ есть номер формата `48:20:0000000:123`.
- **Район не определён** — в ТУ должны быть признаки одного из поддерживаемых районов/городов.
- **Координаты участка не найдены** — кадастровые API недоступны или номер не найден в реестре.
- **Routing API недоступен** — добавьте API-ключ или проверьте сеть.

## Ручной выбор провода

На сайте в форме обработки есть поле **Провод**:

- **Автоматически** — режим по умолчанию, работает существующая логика из `tu_parser.py`;
- **3\*70+1\*70**, **3\*50+1\*54,6**, **3\*35+1\*35** — ручной выбор с приоритетом над автоматическим.

### Как это работает

1. Система сначала определяет провод из ТУ автоматически (`SECH_KABEL`).
2. Если выбран ручной режим, итоговый провод берётся из выбора пользователя.
3. Вес и все расчёты (`SECH_KG`, ведомости, DWG-записка) используют только итоговые значения:
   - `wire_final_value`
   - `wire_weight_final`

Ручной режим не меняет автоматическую логику — он добавляет override поверх неё.

### Справочник проводов

Файл: `config/wire_catalog.json`

Пример записи:

```json
"3*70+1*70": {
  "label": "3*70+1*70",
  "sech_kabel": "3x70+1x70",
  "weight_kg_per_km": 1112,
  "weight_source": "calculator.py — существующая формула для 3x70+1x70"
}
```

- `label` — значение в интерфейсе.
- `sech_kabel` — строка для placeholder `{{SECH_KABEL}}` в DWG.
- `weight_kg_per_km` — вес провода в кг/км для формулы `SECH_KG = SECH_KM * weight`.

### Как добавить новый провод

1. Добавьте запись в `config/wire_catalog.json`.
2. Добавьте option в `frontend/index.html` (select `#wireSelect`).
3. Укажите `weight_kg_per_km` — без веса ручной выбор вернёт ошибку.

### Если вес не задан

При ручном выборе провода без веса API вернёт ошибку:

`Для выбранного провода не задан вес. Заполните вес в справочнике проводов.`

В справочнике `config/wire_catalog.json` заданы веса (кг/км):

| Провод | Вес |
| --- | --- |
| 3\*70+1\*70 | 1112 |
| 3\*50+1\*54,6 | 775 |
| 3\*35+1\*35 | 566 |

В автоматическом режиме для проводов `3x70+1x70` и `3x50+1x50` по-прежнему используются коэффициенты **1112** и **775**.

## PDF записки 1:1 с DWG

PDF пояснительной записки формируется **напрямую из готового `note_result.dwg`**, а не через ezdxf-рендер DXF.

Приоритет экспорта:

1. `DWG_PDF_EXPORT_COMMAND` / `pdf_export.external_command` в `config/settings.json`
2. AutoCAD Core Console (Windows)
3. **QCAD `dwg2pdf`** (macOS / Linux / Windows)

Установка QCAD на macOS:

```bash
brew install --cask qcad
```

Путь к утилите задаётся в `config/settings.json`:

```json
"pdf_export": {
  "qcad_dwg2pdf_path": "/Applications/QCAD.app/Contents/Resources/dwg2pdf",
  "qcad_args": ["-no-gui", "-no-dock-icon", "-f", "-a", "-auto-orientation"]
}
```

Рендер через ezdxf (`filled_temp.dxf`) отключён по умолчанию, потому что он **не совпадает 1:1** с DWG. Для отладки можно включить fallback:

```bash
export ALLOW_EZDXF_PDF_FALLBACK=1
```
